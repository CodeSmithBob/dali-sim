Commissioning (addressing)

Units without a short address are found with the random-address binary search: INITIALISE, RANDOMISE, then COMPARE / SEARCHADDR until the lowest random address is isolated, PROGRAM SHORT ADDRESS, WITHDRAW, repeat.

Pre-compliance test bench

Checks protocol behaviour against the public DALI literature: answers, send-twice handling, reset values, limits, groups, scenes, fading, memory bank 0, instance configuration and address conflicts. These are not the official DALI Alliance certification tests; use them to find problems before you go to a test house. Run them against virtual units, or against real ones through a hardware bridge.

Hardware bridges

Start a bridge from the command line, for example:

dali-sim serve examples/office-16.yaml --adapter hasseb --bridge-mode controller dali-sim serve examples/office-16.yaml --adapter serial:/dev/ttyUSB0 --bridge-mode devices dali-sim serve examples/office-16.yaml --adapter remote:192.168.1.20:5555 --bridge-mode hybrid

controller: the simulator drives real devices. devices: a real controller drives the virtual devices (answers need an adapter that can send backward frames). hybrid: virtual and real devices act as one bus.

How to use

  • Installation: lamps glow with their light output (DT8 lamps in their colour). Click a lamp for its variables and controls. Hold the push buttons, move sliders, toggle occupancy and set the daylight to drive the application controller rules.
  • Bus monitor: every frame with timing and decoding. Click a row to see its Manchester waveform.
  • Console: send any IEC 62386-102/103 command. Configuration commands are sent twice automatically.
  • Commissioning: clear addresses, then watch the binary search find every unit.
  • Test bench: pre-compliance checks on virtual or real units.

The TCP API on port 5555 and the REST API under /api are described in the docs folder of the repository.
